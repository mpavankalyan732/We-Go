# RoadLink Bus Booking — Website (Phase 1)

Single-page bus booking website. React + Vite, no backend yet — see
**Architecture** below for how this plugs into later phases.

## Run it

```bash
npm install
npm run dev
```

Open the printed local URL (typically http://localhost:5173).

## Flow implemented

Search → Results → Seat Selection → Passenger Details → Payment (simulated) →
Confirmation, plus a standalone **Track Booking** lookup (top-right nav) that
retrieves a booking by its reference ID.

## Architecture — the Phase 3 seam

All bus/seat/booking data flows through **one module**:
[src/api/busApiService.js](src/api/busApiService.js). Every UI component calls
functions from this file only — nothing reads mock data directly. Today it's
backed by an in-memory mock ([src/api/mockProvider.js](src/api/mockProvider.js))
that mimics the real external Bus API's contract exactly:

| Function | Will call |
|---|---|
| `searchBuses` | `GET /api/buses/search` |
| `getTrip` | `GET /api/trips/:tripId` |
| `getSeatMap` | `GET /api/trips/:tripId/seats` |
| `createBooking` | `POST /api/bookings` |
| `getBooking` | `GET /api/bookings/:bookingReferenceId` |

**To go live in Phase 3** (once the Node/Express Bus API from Phase 2 is
deployed): set `API_BASE_URL` in [src/api/config.js](src/api/config.js) and
flip `USE_MOCK_API` to `false`. No component or state code changes.

## Project structure

```
src/
  api/            busApiService (public contract), mockProvider (stand-in backend), config (Phase 3 switch)
  context/        BookingContext — booking flow state machine (useReducer)
  components/
    layout/       Header, StepProgress
    search/       SearchForm
    results/      ResultsList, BusCard
    seats/        SeatSelection, SeatMap, SeatLegend
    passengers/   PassengerForm
    payment/      PaymentForm (simulated payment)
    confirmation/ ConfirmationCard, BookingSummaryCard (shared with Track Booking)
    track/        TrackBooking
    common/       Loader, ErrorBanner
  utils/          formatters, validators, cities (autocomplete only)
```

## Notes

- Booking reference IDs and PNRs are generated by the mock provider (standing
  in for the external API) — never by a UI component — so this stays true once
  swapped for the real service.
- Payment is simulated (card fields are format-validated only, no gateway
  call). The seam for a real gateway is called out in
  [PaymentForm.jsx](src/components/payment/PaymentForm.jsx).
- Seat maps regenerate deterministically per trip (same trip always shows the
  same layout for the session) and seats lock to `booked` in the mock provider
  once a booking is created, so re-searching reflects real availability.
